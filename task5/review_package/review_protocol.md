# 实验5独立语义核验规范

## 任务与审核身份

请作为独立语义审核者，仅依据随附原文审查现有预测，不调用原抽取模型，不凭旅游常识补写。待审状态不表示预测正确或错误。自动隔离理由只是原系统的决策依据，允许推翻。原模型对C、D的空输出也不是独立审核结论。

本次由另一个ChatGPT对话完成的判断应标为“独立LLM辅助语义审核”，不得写成真实人工金标准。若后来由学生或教师逐条确认，请另记审核人和确认日期。

## 阅读顺序与可追溯材料

先阅读本文及README，再分别审查A–E。每条都有文档ID、原始窗口、上下文；遇到“这里”“路线3”“左线”等，请在Excel `F_SourceDocuments`或 `F_source_documents.json`查找同文档的完整清洗文本，不用猜测。

- A：全部保留关系，审查FP、Boundary、Association、Classification，并对全表比对剩余重复。
- B：全部自动隔离关系，判断是否该恢复；原输出边界错误时可建议纠正后恢复。
- C：当时实际抽查的全部36个规则外窗口，找候选筛选阶段FN。
- D：20个规则已命中但原模型对该窗口输出空列表的样本，找语义抽取阶段FN。
- E：全部实际合并组，检查过度合并、规范化错误与来源丢失；组内所有成员在 `E_MergeMembers`展开。
- G：若非空，为此前保守保留的近重复候选。G为空不意味着A没有重复，仍须两两比对A。

## 有效关系标准

1. 条件有可定位的原文依据，表达建议的适用情境、限制、偏好或对象；不能凭景区名或一般旅游常识创造条件。
2. 建议是可执行的行动、选择或行为调整，如购票、选路线、调整时间、避免某行为。负向建议同样有效。普通事实、历史叙述、景色评价、修辞效果或可能发生的后果，本身不等于建议。
3. 条件与建议确有适用关系，不是仅在同一句中出现。纯路线先后与真正情境限制需结合语义判断，不能仅看触发词。
4. 一个条件可对应多个建议。并列行动可拆为多条，但不能碎片化为无意义宾语、补语或缺少指向的“适合”“慎选”。若原文明确指向前文路线，可以据上下文判定有效，并指出建议边界需扩展或补充来源指向。
5. 无条件的“建议提前购票”不能凭空配上条件；但相邻句、标题或段落明确给出适用对象时，可按原文判断隐式或跨句关系。
6. 保留否定、程度、时间方向和限定范围。“不容易晕”不得截成“容易晕”。“下午3点后不宜，记得上午去”不能机械配成“下午3点后→上午去”。
7. 组合条件整体判断，不能无依据拆成每个子条件都单独成立。反之，原文确实列出多个独立适用对象时，说明是否允许分别建立关系。
8. 原始证据、source_text和上下文均为逐字文本。模型预测字段可能不满足子串约束，这正是审核对象；不能把预测字段误认为原文。
9. 原文自身的错字、脱敏拼写、表情和过时信息不应在本次任务中改写成事实。这里只核验文本关系，不审核当前旅游政策真实性。

## 错误标签

| 标签 | 判定问题 | 返回内容 |
|---|---|---|
| FP | A关系在原文中不成立，或事实/修辞被当行动 | 原因及是否删除 |
| FN | C、D或B中存在未保留的有效关系 | 条件、建议、类别与逐字证据 |
| Boundary | 关系大体成立，但边界截断、混入理由、否定丢失等 | 原预测与建议修正边界 |
| Association | 条件和建议接错、方向倒置、跨段错配 | 正确关联或无法成立原因 |
| Classification | 关系有效但主类别不合适 | 修正类别及原文依据 |
| Deduplication | 该合并未合并，或合并吞掉不同条件/行动/范围 | 涉及ID、合并/拆分建议及理由 |

允许同时标记多个错误。区分“确认问题”“可接受”“上下文不足/存在歧义”。不要为满足数量而强制给结论。C、D中未发现关系时填“未发现”，不要返回无条件建议凑数。B即使过滤理由不妥，也不自动意味着关系有效。

## 条件分类定义

类别按条件含义判断，不按建议中的动作词判断。下表是独立审核使用的操作定义，不修改原预测。

| 类别 | 定义与边界 |
|---|---|
| 游客类型 | 老人、儿童、亲子、婴儿车陪同、初访者等对象或经验群体；“想拍照”优先是偏好而非游客类型 |
| 天气环境 | 雨、晴、高温、风、光线等外部环境；季节若因气候生效可用此类，若仅表示旺淡季/日历安排则优先时间约束 |
| 时间约束 | 可用时长、赶时间、时段、旺淡季、节假日等安排限制；仅人多拥挤而无时间含义不应自动归为时间 |
| 体力与健康 | 体能、疲劳、步行承受、初入高原反应、晕动等生理限制；按实际条件判断，不能把所有带老人都自动改为健康 |
| 交通条件 | 自驾、公交、交通接驳、通行方向、运输方式适用限制；若条件是体力不足、建议是坐车，类别仍优先体力健康 |
| 游览偏好 | 想拍照、喜欢历史、想安静欣赏、重视某类体验等目标偏好 |
| 其他条件 | 真实存在且不适合以上类别的情境，如仅拥挤而无时间信息；不得作为普通事实或无条件建议的收容类别 |

多个类别同时成立时保留完整组合条件，选择直接限制行动的主类别并解释，也可另列次类别或“类别有歧义”。不要为统一分类而删掉原文限定。

## 去重标准

- 必须同时比较条件与建议，而非只看建议相似。
- 同条件不同建议一般保留多条；同建议但不同适用条件一般保留。
- 比较否定、数字、路线范围、时段与组合条件；字面前后缀相同不意味着语义等价。
- 同原文的重叠窗口重复可以合并，保留所有窗口与偏移；独立来源语义相同也可合并，但不得丢来源。
- E中保留记录不是新证据。请比较全部原成员及合并后文本，确认来源映射完整。

## 返回格式

可以填写Excel空白审核列，也可以返回Markdown表或JSON。每项至少给出：组别、稳定记录ID、结论、错误标签、逐字证据、简要理由；有修正时给修正条件、建议、类别。C、D一个窗口可能遗漏多条，请使用列表而不是覆盖前一条。

推荐JSON：

```json
{
  "review_type": "独立LLM辅助语义审核",
  "reviewer": "填写审核对话或模型标识",
  "items": [
    {
      "group": "填写A/B/C/D/E",
      "record_id": "复制包内ID",
      "decision": "可接受/确认问题/未发现/不确定",
      "error_types": [],
      "evidence": "逐字复制原文",
      "reason": "判断理由",
      "proposed_pairs": []
    }
  ]
}
```

最终报告已审条数、未审条数、各类问题涉及的ID及尚需人工确认事项。不要把C、D的样本漏抽率当作全语料Recall，也不要将A中通过比例写成经人工确认Precision/F1。A/B/C/D/E存在交叉引用，不能将各组记录数相加作为独立语义样本总量。
