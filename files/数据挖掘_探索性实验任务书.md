# 2026《数据挖掘》探索性实验任务书及评分细则

## 实验主题

**景区游览指南的程序性知识挖掘**

---

## 一、评分总体原则

1. 本细则采用“**核心功能完成度 + 方法合理性 + 结果质量 + 分析解释 + 可复现性**”的评分方式。每个实验项目及实验总结独立按 100 分计分，项目内各考核项的分值根据试做反馈中的难度和实际工作量进行分配。

2. 评分以实验目标为准，不绑定唯一技术栈。任务书中给出的 Jieba、LangChain、NetworkX、Neo4j、Eino、AutoGen 等均可用等价方法替换；只要达到相同功能目标、结果可验证，即按相同标准评分。

3. 允许使用 LLM 辅助编程或分析，不因使用 LLM 本身扣分。学生应能说明关键方法、规则 / Prompt、输入输出和验证方式；仅粘贴生成代码或截图、不能解释其作用时，相应“方法 / 实现 / 分析”项不能给满分。

4. 报告、源代码和输出结果应相互对应。截图可作为运行证据，但不能替代可检查的代码、结构化结果文件和关键中间产物。

5. 完全照抄参考代码、他组代码或公开项目且无法说明核心逻辑时，相关实现考核项记 0 分。

## 实验项目 1：景区指南数据采集与预处理

### 对应科研点

基础数据工程（支撑所有后续研究）。

### 实验目标

获取景区指南相关数据，并处理成合适的格式，为后续知识抽取与挖掘奠定数据基础。

### 实验主要内容

1. **数据采集**
   - 使用自动化工具采集 3 个景区的官方游览推荐路线，例如“一日游最佳路线”“亲子游攻略”。
   - 采集对应景区的游客游记，每个景区约 5 篇。
   - 数据来源可包括官方旅游网站、小红书攻略、马蜂窝游记等。
   - 受探索性实验课时限制，也可使用教师提供的参考数据集：`IndustryCorpus2_tourism_geography`。

2. **数据预处理**
   - 去除 HTML 标签。
   - 去除元数据、网址、特殊字符等噪声。
   - 统一空白、换行、标点或编码格式。
   - 处理明显乱码与冗余内容。
   - 将数据整理为结构化文件，至少包含：
     - 来源
     - 景区
     - 文本类型
     - 原始内容

### 实验技术方法

- 爬虫：browser-use、requests + BeautifulSoup、Selenium 等。
- 数据清洗：正则表达式、Python 字符串处理、pandas。
- 数据存储：Excel、CSV 或 JSON。

### 实验主要步骤

1. 选择数据获取方式。
   - 若使用爬虫，配置工具抓取指定景区数据。
   - 若使用教师提供数据集，则直接加载并熟悉数据结构。
2. 编写 Python 脚本对原始文本进行清洗与格式化。
3. 输出规范化 Excel / CSV / JSON。
4. 检查数据质量。
5. 确保每个景区至少包含：
   - 1 条官方路线
   - 3 篇有效游客游记
6. 保存最终数据集。

### 评分细则

| 考核项 | 分数 | 评分细目 |
|---|---:|---|
| 数据准备与来源规范 | 20 | 按任务要求准备 3 个景区数据；原则上每景区至少 1 条官方推荐路线及若干有效游客游记；说明数据来源、景区名称、文本类型等；自行采集需提供可复现采集方法 / 脚本或过程说明；使用教师数据集需说明加载方式、字段含义与来源 |
| 数据清洗与预处理实现 | 40 | 能批量读取原始数据并完成处理；去除 HTML、网址 / 无关元数据、异常符号等；统一空白、换行、标点、编码格式并处理乱码与冗余；处理或检查空值、重复记录、异常字段；关键清洗规则有合理解释，代码结构清晰 |
| 结构化输出与数据质量验证 | 25 | 输出规范化 Excel / CSV / JSON；给出清洗前后样例或对比；检查各景区数据数量、缺失、重复和格式一致性，并说明问题 |
| 报告与可复现性 | 15 | 给出依赖、运行命令 / 入口、输入输出路径；报告包含关键代码 / 流程说明及代表性结果；说明采集或清洗过程中的问题及处理方式 |

## 实验项目 2：游览步骤的实体识别

### 对应科研点

基于大语言模型和归纳推理的实体类型识别。

### 实验目标

识别程序性文本中的核心要素：

- 景点 POI
- 交通方式
- 时间节点

### 实验主要内容

1. **实体识别**
   - 使用 Jieba 分词 + 自定义词典，或使用 LLM / LangChain 等方法。
   - 从实验 1 预处理后的文本中识别三类实体：
     - 景点 POI
     - 交通方式
     - 时间节点

2. **归纳推理**
   - 对比多个景区识别结果。
   - 归纳适用于景区领域的实体类型体系。
   - 形成实体定义规范表。

3. **可视化分析**
   - 绘制各类实体词频图。
   - 可使用词云或柱状图。
   - 根据结果添加停用词，迭代优化实体提取质量。

4. **成果输出**
   - 实体定义规范表。
   - JSON 格式实体文件。
   - 实体出现位置。
   - 词频可视化图表。

### 实验技术方法

- Jieba 分词与自定义词典。
- LLM 调用与 Prompt 设计。
- Matplotlib、WordCloud。
- JSON 数据存储。

### 实验主要步骤

1. 构建自定义词典，或设计实体识别 Prompt。
2. 批量处理多个景区文本。
3. 统计实体词频。
4. 绘制词云 / 柱状图。
5. 根据可视化调整停用词、领域词典或规则。
6. 重新识别并比较优化前后结果。
7. 导出实体规范表、JSON 和可视化图表。

### 评分细则

| 考核项 | 分数 | 评分细目 |
|---|---:|---|
| 实体类型定义与规范 | 15 | 明确 POI、交通方式、时间节点三类实体的定义、边界和示例；定义在多个景区之间保持一致，并说明易混淆情况 |
| 实体识别方法实现 | 35 | 使用 Jieba + 自定义词典、规则或 LLM 等方法完成识别；词典 / 规则 / Prompt 设计合理；支持多景区批量处理；保留实体类型、来源及出现位置 |
| 识别结果与质量检查 | 20 | 输出结构化实体文件；人工抽查样例，分析误识别、漏识别和歧义；结果无明显大规模噪声、重复或类型混乱 |
| 词频可视化与迭代优化 | 20 | 统计三类实体词频并生成词云 / 柱状图；根据结果调整停用词、领域词典或规则，并说明优化前后变化 |
| 报告与可复现性 | 10 | 说明方法选择、主要参数 / 词典 / Prompt、运行方式、输入输出及代表性结果，关键步骤可复现 |

## 实验项目 3：游览路线的层级结构挖掘

### 对应科研点

面向程序性文本的层级结构挖掘技术。

### 实验目标

挖掘游览路线的层次结构，理解官方指南与游客游记中路线组织的差异。

### 实验主要内容

1. **官方路线结构化解析**
   - 分析官方推荐路线的文本描述方式。
   - 归纳格式规律，例如：
     - 箭头链路
     - 编号列表
     - 按时间分段
   - 设计解析规则。
   - 统一输出：
     - 步骤序号
     - 时间
     - 景点
     - 活动

2. **时间维度层级构建**
   - 基于解析结果构建：
     - 上午
     - 中午
     - 下午
   - 输出结构化路线数据。

3. **高阶任务：官方与游客路线对比**
   - 选取同一景区的官方推荐路线与游客游记中的实际路线。
   - 比较：
     - 时间分配
     - 景点顺序
     - 停留时长
     - 覆盖度
     - 路线相似度
   - 分析差异原因。

### 实验技术方法

- 正则表达式。
- 字符串模式匹配。
- Python 字典、列表。
- JSON / CSV。
- 手工或脚本计算结构相似度。

### 实验主要步骤

1. 选取 1—2 个景区的官方路线文本。
2. 分析文本描述模式。
3. 编写解析函数。
4. 输出结构化 JSON。
5. 构建时间维度层级。
6. 如选做附加题，提取游客路线并进行对比。
7. 输出结构化数据和分析结果。

### 评分细则

| 考核项 | 分数 | 评分细目 |
|---|---:|---|
| 官方路线模式分析与结构化解析 | 40 | 分析不同路线文本描述模式；设计统一表示，至少包含步骤 / 时间 / 景点 / 活动；编写解析程序，能够处理至少 1—2 种典型格式 |
| 时间维度层级结构构建 | 40 | 构建上午 / 中午 / 下午或等价层级；合理组织景点、活动及先后关系；输出层级数据和 / 或清晰结构图 |
| 官方路线与游客实际路线对比（附加题） | 20 | 将游客实际路线转为可比较表示；至少从两个维度进行量化或结构对比；结合结果分析差异原因。附加后总分仍封顶 100 分 |
| 名称归一化、噪声处理与稳健性 | 10 | 处理简称 / 全称、俗称 / 正式名、子景点 / 父区域、周边景点和重复实体；避免明显过度对齐，并说明规则局限 |
| 报告与可复现性 | 10 | 说明解析规则、数据结构、指标计算方式、运行命令和输出文件，给出代表性中间结果 |

## 实验项目 4：程序性知识的共指消解

### 对应科研点

先行词共指消解技术。

### 实验目标

解决文本中“它、这、那里、他们”等指代不明确的问题。

### 实验主要内容

1. **代词检测**
   - 使用正则和分句方法检测代词。
   - 保存代词所在句子和位置。

2. **指代消解**
   - 至少实现一种方法，例如：
     - 最近名词 / 实体匹配规则
     - 现有共指消解模型
     - 简单分类模型
     - LLM 推理

3. **效果评估**
   - 建立人工标注。
   - 人工验证结果。
   - 统计准确率、覆盖率等。
   - 输出消解后的文本或知识三元组。

### 实验技术方法

- 正则表达式。
- Jieba。
- Transformers 或其他共指模型。
- 自建规则。
- LLM 推理。
- 人工评估。

### 实验主要步骤

1. 从 3—5 篇游记中提取含代词句子。
2. 生成待消解样本。
3. 保存代词位置、来源、句子等。
4. 建立人工标注。
5. 实现并运行消解方法。
6. 人工评估至少 5 个案例。
7. 总结方法优缺点。
8. 输出消解结果。

### 评分细则

| 考核项 | 分数 | 评分细目 |
|---|---:|---|
| 代词检测与样本构建 | 20 | 能检测“它、这、那里、他们”等代词及所在句子；保存代词位置、来源文本等，避免同句多个相同代词错配 |
| 人工标注 | 20 | 对待消解样本标注真实先行词，至少给出若干可核验案例（建议不少于 5 个）；标注字段和类型定义一致，并能处理无明确先行词等情况 |
| 指代消解方法实现 | 30 | 实现至少一种消解方法；规则 / 模型逻辑与旅游文本特点匹配，如 POI 优先、距离 / 类型约束；输出消解结果、文本或三元组 |
| 效果评估 | 20 | 使用人工标注计算或核验准确率、覆盖率等指标 |
| 报告与可复现性 | 10 | 说明样本构建、标注格式、算法逻辑、运行方式和评价方法，结果可复核 |

## 实验项目 5：条件性游览建议的抽取

### 对应科研点

程序性知识的复杂依赖关系抽取。

### 实验目标

挖掘文本中的条件逻辑，例如：

- “如果下雨，则……”
- “如果带老人，则……”
- “如果亲子游，则……”

### 实验主要内容

1. **条件触发词识别**
   - 识别：
     - 如果
     - 假如
     - 若
     - 建议
     - 可以
     - 等典型条件或建议表达
   - 提取条件部分和建议部分。

2. **映射表构建**
   - 构建“条件 → 建议”映射表。
   - 字段可包含：
     - 条件类型
     - 条件描述
     - 建议内容
     - 来源景区
     - 来源文本

3. **分类与统计**
   - 按游客类型或条件类型分组。
   - 绘制对比柱状图。

### 实验技术方法

- 正则表达式。
- LTP、HanLP 或其他语义角色标注工具。
- LLM。
- pandas。
- Matplotlib。

### 实验主要步骤

1. 从游记和官方指南中批量抽取条件建议。
2. 生成人工可核验的初步映射表。
3. 人工校验并补充缺失条件。
4. 去重与分类。
5. 保存 JSON / Excel。
6. 按游客类型或条件类型统计。
7. 绘制图表。

### 评分细则

| 考核项 | 分数 | 评分细目 |
|---|---:|---|
| 条件触发词与抽取规则设计 | 30 | 覆盖“如果 / 假如 / 若 / 建议 / 可以”等表达；规则、语义方法或 LLM Prompt 能识别条件与建议；说明规则优先级或适用边界 |
| 条件—建议信息抽取 | 35 | 批量抽取条件—建议对并保留来源；人工抽查误抽、漏抽和边界切分；对多建议句、跨分句表达等有基本处理 |
| 映射表构建、分类与去重 | 25 | 输出包含条件类型、条件描述、建议内容、来源等字段的结构化映射表；合理分类；处理同句重复、近重复和前后缀重复 |
| 报告与可复现性 | 10 | 说明规则 / 模型、映射表字段、运行方式、结果样例与主要问题，能够复现核心输出 |

## 实验项目 6：多源程序性知识的融合与图谱可视化

### 对应科研点

知识图谱构建与表示。

### 实验目标

将官网、游记等不同来源的知识整合，并进行图形化展示。

### 实验主要内容

1. **数据融合**
   - 读取并关联：
     - 项目 2 的实体
     - 项目 3 的路线结构
   - 必要时融合：
     - 项目 5 的条件性建议
   - 建立实体间关联。

2. **图谱构建**
   - 使用 Neo4j、NetworkX 或等价方案。
   - 定义节点类型，例如：
     - 景点
     - 操作 / 活动
     - 时间
     - 条件
   - 定义关系类型，例如：
     - 先后顺序
     - 条件关系
     - 包含关系

3. **可视化**
   - 展示至少一个景区较完整的游览知识网络。
   - 突出关键节点和关系。

### 实验技术方法

- Neo4j / Cypher。
- NetworkX。
- PyVis。
- Matplotlib。
- Python JSON 数据处理。

### 实验主要步骤

1. 整合项目 2、3 的输出。
2. 设计节点和边 Schema。
3. 如有需要，融合项目 5 条件建议。
4. 生成节点和边结构化文件。
5. 导入 Neo4j 或使用 NetworkX 构图。
6. 编写查询 / 绘图代码。
7. 保存可视化结果。
8. 分析核心节点、典型路径及缺失 / 异常关系。

### 评分细则

| 考核项 | 分数 | 评分细目 |

| 知识图谱模式设计与构建 | 30 | 定义节点类型和关系类型；使用 NetworkX、Neo4j 或等价方式实际构建图；生成可读取结构化文件 / 数据库，并保证基本连通关系正确 |
| 图谱可视化 | 20 | 至少展示一个景区较完整图谱；节点类型、边类型和关键关系可辨识；布局和过滤合理，突出关键节点 / 路径 |
| 图谱质量验证与分析 | 10 | 通过查询、统计或人工检查验证节点 / 边；分析核心节点、典型路径、缺失关系或数据质量问题 |

## 实验项目 7：程序性知识应用——旅游规划 Agent

### 对应科研点

基于知识图谱和 LLM 的问答与生成。

### 实验目标

基于已构建的知识图谱，结合 LLM 与 Agent 技术，实现一个“旅游规划 Agent”。

该 Agent 应能够：

1. 理解用户自然语言请求。
2. 提取用户约束。
3. 查询知识图谱。
4. 根据查询结果进行路线规划。
5. 生成个性化游览建议。

### 实验主要内容

#### 1. Agent 框架设计

采用 ReAct 或等价的“解析 / 决策 → 工具调用 → 读取结果 → 生成回答”闭环。

核心模块可包括：

- 意图 / 约束解析器
- 图谱查询工具
- 路线规划器
- LLM
- 回答生成模块

#### 2. 约束解析

从用户输入中提取：

- 景区
- 游客类型
- 时长
- 条件限制
- 其他偏好

例如：

- “带孩子” → 亲子约束
- “一天” → 时间限制
- “带老人” → 老人友好
- “不想走太多路” → 低步行偏好

#### 3. 图谱查询工具

将项目 6 的知识图谱封装成 Agent 可以真实调用的工具。

> 仅将图谱内容写入 Prompt 不等于工具封装。

工具应定义：

- 工具名称
- 输入参数
- 输出 Schema
- 返回结构
- 无结果 / 异常情况

#### 4. 路线规划

结合图谱查询结果与 LLM 的常识知识，生成：

- 游览顺序
- 时间安排
- 注意事项
- 条件性建议

#### 5. 交互入口

提供：

- CLI
- Web 界面
- 或其他可用入口

### 实验技术方法

- OpenAI API、HuggingFace Transformers、本地模型等。
- LangChain、AutoGen 或自行实现的 Agent 框架。
- 工具调用。
- Prompt Engineering。
- JSON / 自然语言输出。

### 实验主要步骤

1. 搭建 Agent 基础框架。
2. 实现 LLM 调用。
3. 封装图谱查询工具。
4. 设计 Prompt。
5. 实现闭环 Agent 流程。
6. 调试工具调用与查询结果使用。
7. 测试多个场景，例如：
   - 带老人游玩
   - 亲子游
   - 情侣一日游
   - 一天 / 两天
   - 不同景区
8. 测试异常场景：
   - 无匹配
   - 信息不足
   - 冲突约束
9. 输出最终规划方案与完整执行记录。
