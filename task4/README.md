# 实验项目 4：程序性知识的共指消解

读取实验 1 的 18 篇正式文本和实验 2 的 V2 实体结果，检测代词/指示表达，生成候选先行词，并用可复现的规则完成共指消解。选取 5 篇游客游记，从其中的 54 个提及中人工标注 28 条，输出逐位置结果、消解文本和知识三元组。Python 3.10+，仅标准库，不调用模型，不需要 API 密钥。

从仓库根目录执行：

```powershell
python -X utf8 task4/run.py
python -X utf8 -m unittest discover -s task4/tests -v
```

脚本路径相对于自身解析，也可以从其他目录用绝对路径运行。重跑会覆盖 `task4/results/` 的派生结果，不修改任务 1、2、3 的输入。

## 检测口径

代词检测使用正则表达式，按最长表面优先匹配，覆盖：

- 人称：我、我们、你、你们、他、她、它、他们、她们、它们、自己、大家；
- 地点：这里、这儿、那里、那儿、这边、那边、此处、此地；
- 指示：这、那、这个、那个、这些、那些、这种、那种、这样、那样；
- 书面指代：此、该、其。

分句使用句末标点、分号和换行，不依赖 Jieba 分词。代词是字符级模式，直接使用正则和原文偏移可以保证 `clean_text[start:end]` 与代词完全一致；分词不会改善这个边界，反而增加词典依赖。

检测阶段同时做三类过滤：

1. **固定搭配**：`其他`、`其实`、`尤其`、`从此`、`此时`、`该坐` 等不当作代词。
2. **篇章/时间用法**：`这次`、`这时`、`这期间`、`这么` 等保留为话语标记或不进入消解。
3. **非实体短语**：`这些照片`、`这个历史疑案`、`这句话`、`这种布局` 等标为 `non_entity`，避免强行绑定到最近景点。

每个提及用 `(doc_id, start, end)` 唯一定位，不使用代词字符串作为键。同一句出现两个“这里”时，位置不同，记录也不同。

## 标注口径

`annotations.json` 的 `status` 只有两种：

- `clear`：原文有可定位、可核验的先行词；
- `no_antecedent`：代词指向篇章语境、泛称或无可定位实体，允许系统弃权。

标注使用原文 `clean_text` 的 Python Unicode 码点，0 起点，左闭右开。明确先行词既可以是 POI（如“午门”“柳浪闻莺”），也可以是路线段（如“原始森林 → 芳草海 → 天鹅海”）、路线名（如“乌龟潭路线”）或人物名词（如“娃”）。

标注规则：

- 标题和小节名可以成为先行词，例如“乾清宫｜帝王日常”后的“这里”指乾清宫。
- “这道门/这座皇城/这座围墙”按中心名词回指，分别指午门、紫禁城。
- “这一段/这条路线”优先绑定前文箭头链或路线名，而不是外层章节名“右线”。
- 指向下文的“这里特别提醒”不强行回指前文，标为 `no_antecedent`。
- 第一、第二人称和泛称（我、我们、你、大家、自己）不计入实体共指评估，但仍保留在检测结果中。

## 消解方法

候选先行词来自五类：

1. 实验 2 的 POI 和 TRANSPORT 实体；
2. 以 `｜`、`📍`、编号或短标题行识别的小节标题；
3. 含 `→` 的路线链，用路线 POI 词表提取首末节点，得到连续路线段；
4. “POI + 路线”构成的复合路线名，例如“乌龟潭路线”；
5. 人物名词词表（孩子、娃、小朋友、老人、家长、作者、同伴、家人）。

打分特征包括：代词类型与候选类型是否兼容、候选来源（标题/路线段/路线/实体/人物）、当前小节标题、句距、字符距离、中心名词匹配、路线中心词提示、候选词频和长度。权重和阈值集中在 `extract.py` 顶部，便于复核。

处理难点：

- **标题优先于背景实体**：同一小节里的“这里”优先绑定当前标题，而不是更近但只作背景提及的“紫禁城”。
- **路线段优先于章节名**：“这一段”“这条路线”优先绑定箭头链；外层“右线”只作为章节标签，不抢走路线段。
- **中心名词约束**：“这道门”只找含“门”的 POI，“这座皇城/围墙”只找紫禁城/故宫类候选。
- **保守弃权**：候选分数低于阈值、前两名差距过小，或“这里”指向两段以前的路线段时，输出 `no_antecedent` 或 `ambiguous`。

全语料 18 篇中 16 篇检测到代词，共 162 个提及；55 个已消解，24 个无明确先行词，11 个歧义，23 个非实体短语，49 个第一/第二人称或泛称不计入实体评估。

|---|---:|
| 标注总数 | 28 |
| 明确先行词 | 26 |
| 无明确先行词 | 2 |
| 已消解 | 26 |

| 正确弃权 | 2 |
| 覆盖率 | 100.00% |
| 已消解准确率 | 100.00% |
| 总体准确率（含弃权） | 100.00% |

分类结果：地点代词 11 条（10 条明确 + 1 条无先行词）、指示代词 4 条、指示限定 12 条（11 条明确 + 1 条无先行词）、第三人称 1 条。

28 条上的满分只说明当前规则与这批定向标注一致，不代表全语料准确率。规则是在同一批文本上设计的，没有独立测试集；非标注文本中仍能看到篇章指代、集合指代和人物代词的错误或弃权。

## 输出字段

核心字段沿用根目录 `SCHEMA.md` 第 9 节：

- `coref_id`、`doc_id`、`pronoun`、`pronoun_start/end`；
- `antecedent`、`antecedent_start/end`；
- `method`、`confidence`。

扩展字段：

- `pronoun_type`：place / demonstrative / determiner / person_third 等；
- `antecedent_type`：POI / ROUTE_SEGMENT / ROUTE / TRANSPORT / PERSON；
- `sentence`、`sentence_start/end`：代词所在句；
- `mention_id`：与 `mentions.json` 对接；
- `replace_text`：消解文本中实际替换的完整短语（如“这条路线”），避免只替换“这”后留下“条路线”。

`resolved_texts.json` 同时给出：

- `resolved_text`：把完整指代短语替换为先行词后的文本；
- `marked_text`：保留原词并插入 `〔→先行词〕` 的可核对文本；
- `resolved_sentences`：逐句的原文、替换结果、标记结果和提及 ID。

`triples.json` 的谓词固定为 `referred_by_pronoun`，用于把先行词和代词连成可追溯三元组；具体语义仍应回到 `sentence` 和原文位置核对。

## 验证与边界

17 项测试覆盖分句位置、最长匹配、固定搭配过滤、同句同形代词、hashtag 过滤、中心名词分类、替换短语边界、标题消解、路线段消解、篇章指代弃权、宫城别名、Unicode 位置和 28 条标注评估。每次运行还校验：

- 18 篇文档的 `doc_id` 唯一；
- 1,415 条 V2 实体的位置和原文切片一致；
- 28 条标注的代词、先行词和句子切片一致；
- 检测提及的 `start/end` 与 `clean_text` 一致。

已知限制：

- 只做规则消解，没有训练分类器或调用神经共指模型；
- 人工标注是 5 篇游记的定向样本，不是全语料 gold；
- 第一/第二人称、集合指代、人物姓名和跨段篇章指代只做保守处理；
- 路线段作为先行词时，替换后的句子可能较长或不够自然，`marked_text` 更适合人工阅读；
- 官方指南中“她”指故宫、“他们”指前三殿等拟人/集合表达可能弃权或标为歧义。

来源文本是实验归档内容，票务、开放时间和健康相关表达只作为抽取对象，不作为实时出行建议。
