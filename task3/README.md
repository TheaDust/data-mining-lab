# 实验项目 3：游览路线的层级结构挖掘

覆盖北京故宫、杭州西湖和九寨沟的全部三篇正式官方指南，并选取每个景区两篇游客文本进行对比，共六篇，其中两篇为推荐攻略、四篇有作者自述依据。Python 3.10+，数据处理只用标准库；运行全程离线，不需要 API 密钥。

从仓库根目录执行：

```powershell
python -X utf8 task3/run.py
python -X utf8 -m unittest discover -s task3/tests -v
```

脚本路径相对于自身解析，也可从其他目录用绝对路径运行。重新运行会覆盖 `task3/results/` 中的派生结果，不修改任务 1、2 的输入。

## 格式规则

1. **故宫：编号备选路线。** 只解析总览中“路线一～四”，避免再次把正文重复的路线当作新方案。按顶层连字符分步骤。“中轴线+东线”等组合前缀保存在 `components`，不根据猜测展开。正文历史、拍摄点介绍和开放时间不拼进访问序列。
2. **西湖：标题与“途径”链。** 每个标题对应一条路线；兼容单/双破折号、空白、括号及节点内的并列地点。整条路线时长独立保存。括号中的地名保留在步骤证据里，未直接解释成别名或新增访问点；“远眺”记录为观看方式。
3. **九寨沟：方案、Day、时段和箭头。** 分开一日/二日/三日方案；一日游每个带时间区间的原文行是一个步骤，二日/三日箭头链按节点分步骤。三日游第一天的县城→神仙池及前往漳扎镇的叙述单独解析；无序景点清单和游后可选娱乐不加入核心路线。
4. **游客样本。** 保留原先故宫半天攻略、西湖观光车坐船攻略、九寨沟时刻游记三篇，再加入故宫亲子自述、西湖亲测家庭线、九寨沟一日三沟实测线。编号、单条链和时刻行分别解析；有多条重复局部链的实测游记，通过 `include_lines` 明确选定五条主行程链，不把提醒、重复强调及假设重游方案接到路线中。配置中的主行程链缺失时直接报错。

解析器针对本仓库三篇官方指南和六篇选定游客样本设计，不宣称通用于任意网页、无标记叙事或图片路线。其余九篇游记不在本轮选择范围，不记为解析失败。

## 数据字段与时间层级

沿用根目录 `SCHEMA.md` 的 Route/Step 核心字段，增加当前任务需要的证据与层级：

- 路线：`route_id`、`doc_id`、`scenic_spot`、`route_name`、`steps`；另有 `route_kind`、来源 URL、`duration_text`、`duration_evidence`、`components`、`hierarchy`、`issues`。自述样本另存 `experience_evidence`，明确引文来自 `title` 还是 `clean_text`。
- 步骤：`step_id`、`time_text`、`time_period`、`poi`、`activity`；另有 `day`、`pois`、`poi_order`、`evidence`、时间证据、区间/时点分钟值、交通与游览时长、`visit_mode`。
- 每个 `pois` 元素保存原文 `text/start/end`、归一化 `name`、`kind`、`scope` 和可用的 `entity_ref`。`pois` 是原文提及列表：同一步骤可能重复提到同一地点，不代表重复访问。
- `poi_order=explicit` 表示步骤内部有路线顺序；`unspecified` 表示并列地点内部顺序未知；`single` 表示单个或未识别具体地点。跨步骤按 `step_id` 读顺序。
- `kind` 区分 `poi`、`station`、`boundary`、`collective`、`unresolved`；`collective` 包括“三大殿”“树正区域”等未展开集合；`scope=surrounding` 标出神仙池、九寨沟县城、漳扎镇等外围行程，不能因为文档景区为九寨沟就把它们归进九寨沟景区内部。

所有位置以原样 `clean_text` 为基准，Python Unicode 码点索引，从 0 开始，左闭右开。`evidence.text == clean_text[start:end]`。不重新清洗正文，也不使用 UTF-8 字节或 JavaScript UTF-16 偏移。

九寨沟一日游直接使用“上午/中午/下午”标题。游客样本有明确时刻时，使用可复现的分桶规则：11:30 前为上午，11:30–13:30 前为中午，13:30–18:00 前为下午，之后为晚上；这些边界是本实验的归一化约定，不证明作者在该时段用餐。

`null` 表示原文未注明日期或时段。故宫、西湖原文主要给出访问顺序，部分只给总时长，因此保留未知时段；“3小时”不转换成“上午”。二日/三日游有日期但没有时段，则使用“第 N 天→未注明时段”。

层级按证据粒度组织：日内时间明确时采用“路线→第 N 天→上午/中午/下午→步骤”，只有相对日期时采用“路线→第 N 天→未注明时段→步骤”，缺少两者时采用“路线→日期未注明→时段未注明→步骤”。单日方案中的 `day=1` 是路线内日程序号，不是实际日历日期；新增故宫、西湖自述没有日期依据，`day` 保留空值。

当前共 250 步，31 步有日内时段，219 步（87.6%）未注明时段；125 步有相对日程序号。三个互斥覆盖组为：日期与时段均有 31 步、仅日期有 94 步、仅步骤顺序有 125 步。未知标记维持统一结构，不代表补出了时间信息。图示和完整清单共同展示这些层级。

`clock_range_minutes` 只把原文时刻转成当日分钟；多站共享一个区间时不拆分。`visit_duration_text` 与 `travel_duration_text` 分开，均有原文锚点。“参观”作为默认活动时 `activity_inferred=true`，表示解析补充的概括，而不是原文事实。

## 名称、噪声与重复

官方路线的显式节点直接从结构中提取，能保留 V2 漏识别的节点。游客片段使用该位置的 V2 POI 加本景区官方路线名称词表，重叠候选优先保留长名称；全文背景实体不直接进入路线。

仅在九寨沟配置两个映射：`天鹅湖→天鹅海`、`诺日朗中心→诺日朗中心站`。前者依据同一官方指南中的景点概述与相邻路线节点推断，后者依据游记的换乘语境；属于显式规则假设，原词和位置始终保留。单写“诺日朗”仍保留为 `unresolved`，不参与景点指标。其他简称或同义关系不自动推断。

“雷峰夕照/雷峰塔”“南屏晚钟/净慈寺”、父区域/子景点保持不同名称。括号中的别称、遗址、附属地点不直接合并。无序并列节点保留在同一步中，不建立它们之间的先后关系。

新增游客链只在括号前的主节点中匹配地点：例如“花港观鱼（对面就是太子湾公园）”保留整段证据，但访问节点只有花港观鱼。集合“三大殿”不等同于分别证实到访三个殿，“树正区域”不展开为树正沟的所有子景点。集合、未消歧名称及交通站保留在路线中，排除出具体景点指标。名称处理与不合并的完整案例表见 `REPORT.md` 第 3.4 节；故宫、西湖没有配置别名不代表没有进行边界、层级和噪声处理。

不同备选路线、不同日期可以包含相同景点，不能全局去重。计算路线序列时仅折叠相邻同名提及，保留非相邻的返回访问。覆盖度用集合计算。对内部顺序未知的多地点步骤，顺序比较函数拒绝强行展平；当前选定六组对比路线均具有可读顺序。

## 对比口径

每个景区选定一条官方基准：故宫路线一、西湖十景文化之旅、九寨沟一日精华游，各对应两篇游客样本。原有故宫、西湖样本属于推荐攻略；新增故宫正文自述本次亲子出行、西湖标题声称“亲测”，以及两篇九寨沟自述记录，均保留具体依据。`visitor_actual` 表示作者自述，未提供独立轨迹验证；推荐攻略和自述结果分行展示，不混算为统一的游客实际行为平均值。

在参与对比的景区内部具名景点序列上，排除交通站、泛称出入口、未展开集合、未消歧节点和外围节点。设官方序列为 A、游客序列为 B，集合分别为 U、V：

- 官方景点覆盖率：`|U∩V| / |U|`。
- 景点集合 Jaccard：`|U∩V| / |U∪V|`。
- 顺序相似度：`2 × LCS(A,B) / (len(A)+len(B))`。LCS 为最长公共子序列；只交换访问顺序也会降低此指标。

`strict` 使用原名字面，`normalized` 使用上述限定映射。当前六组对比中两种口径得到相同景点指标：涉及归一化的换乘站被排除，天鹅湖写法仅出现在多日官方方案中。集合未展开和名称粒度差异会降低可确认覆盖率，数值不能直接解释为实际漏游比例。

时间部分列出原文总时长、首末时刻差及显式游览时长条数。九寨沟官方片段为 07:00–17:35，游客为 10:00–17:45，首末差分别为 635 和 465 分钟；不将差值解释为交通/停留时长或效率提升。官方末段时间重叠也会限制此比较。游客没有逐站停留时间，不能由相邻到站时刻反推。

## 验证与已知边界

26 项相关测试覆盖三景区格式、时间层级、并列与括号、共享时段、重叠时刻、外围节点、限定别名、六篇游客截取、集合节点、自述依据、主链配置、Unicode 索引及指标计算。每次运行另检查全部输出的切片、层级与步骤引用。测试使用固定真实语料与少量边界样例，没有进行网络调用或整仓测试。

`python task3/run.py` 会重建 `.drawio` 图稿，SVG/PNG 插图用 draw.io Desktop 另行导出。本机 CLI 位于 `E:\Tools\drawio\draw.io.exe`，未加入 PATH 时可使用绝对路径；将其目录加入 PATH 后可直接调用。导出示例：

```powershell
& 'E:\Tools\drawio\draw.io.exe' --disable-gpu -x -f svg -e -b 12 -o task3/results/hierarchy-overview.drawio.svg task3/results/hierarchy-overview.drawio
& 'E:\Tools\drawio\draw.io.exe' --disable-gpu -x -f png -e -b 12 -s 1.5 -o task3/results/hierarchy-overview.drawio.png task3/results/hierarchy-overview.drawio
```

`results/QUALITY.md` 是可再生成的程序检查及代码辅助复核记录。它不代表学生已经人工签字，也不提供整体 Precision/Recall/F1；提交前应结合原文人工确认。原文可能过时的票务、开放时间不作为本实验的实时旅游建议。

下游读取路线文件时，以 `doc_id` 回查正文，以 `route_id` 区分备选方案；保留 `evidence` 和 `issues`。共享时间段、未展开的 `components`、并列地点和未知时段都需要保留原有语义。
