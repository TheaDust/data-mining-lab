# 实验项目 3：游览路线的层级结构挖掘

覆盖北京故宫、杭州西湖和九寨沟的全部三篇正式官方指南，并选取每个景区一篇游客文本进行对比。Python 3.10+，只用标准库；运行全程离线，不需要 API 密钥。

从仓库根目录执行：

```powershell
python -X utf8 task3/run.py
python -X utf8 -m unittest discover -s task3/tests -v
```

脚本路径相对于自身解析，也可从其他目录用绝对路径运行。重新运行会覆盖 `task3/results/` 中的派生结果，不修改任务 1、2 的输入。

## 输入与输出

| 路径 | 内容 |
|---|---|
| `../task1/data/final/documents.jsonl` | 固定 18 篇的 `clean_text` 和来源信息 |
| `../task2/results/v2/entities.json` | V2 实体位置，辅助游客路线中的景点定位 |
| `samples.json` | 三篇游客样本、截取边界、文体判定与对比理由 |
| `extract.py` | 格式解析、名称处理、层级与对比指标 |
| `run.py` | 输入检查、批量运行、导出与质量记录 |
| `results/official_routes.json` | 17 条官方备选路线，包含步骤和层级 |
| `results/visitor_routes.json` | 三条游客路线：两条攻略推荐，一条作者自述实走 |
| `results/hierarchy.json` | 路线→日期→时段→步骤 ID，步骤详情回查路线文件 |
| `results/hierarchy.md` | 可直接阅读的路线层级清单 |

CSV 中的步骤单位随原文结构而定：可以是一个访问点，也可以是一个共享时间窗的移动/游览段。因此不同景区的步骤数不能直接用于衡量路线复杂度。

## 格式规则

1. **故宫：编号备选路线。** 只解析总览中“路线一～四”，避免再次把正文重复的路线当作新方案。按顶层连字符分步骤。“中轴线+东线”等组合前缀保存在 `components`，不根据猜测展开。正文历史、拍摄点介绍和开放时间不拼进访问序列。
2. **西湖：标题与“途径”链。** 每个标题对应一条路线；兼容单/双破折号、空白、括号及节点内的并列地点。整条路线时长独立保存。括号中的地名保留在步骤证据里，未直接解释成别名或新增访问点；“远眺”记录为观看方式。
3. **九寨沟：方案、Day、时段和箭头。** 分开一日/二日/三日方案；一日游每个带时间区间的原文行是一个步骤，二日/三日箭头链按节点分步骤。三日游第一天的县城→神仙池及前往漳扎镇的叙述单独解析；无序景点清单和游后可选娱乐不加入核心路线。
4. **游客样本。** 故宫截取“半天精华线”编号步骤，西湖截取首个“全程路线”链，九寨沟截取 10:00 入园至 17:45 出园的时刻行。不会把后面的说明、建议或备选方案接到同一路线末尾。

解析器针对本仓库三篇官方指南和三篇选定游客样本设计，不宣称通用于任意网页、无标记叙事或图片路线。

## 数据字段与时间层级

沿用根目录 `SCHEMA.md` 的 Route/Step 核心字段，增加当前任务需要的证据与层级：

- 路线：`route_id`、`doc_id`、`scenic_spot`、`route_name`、`steps`；另有 `route_kind`、来源 URL、`duration_text`、`duration_evidence`、`components`、`hierarchy`、`issues`。
- 步骤：`step_id`、`time_text`、`time_period`、`poi`、`activity`；另有 `day`、`pois`、`poi_order`、`evidence`、时间证据、区间/时点分钟值、交通与游览时长、`visit_mode`。
- 每个 `pois` 元素保存原文 `text/start/end`、归一化 `name`、`kind`、`scope` 和可用的 `entity_ref`。`pois` 是原文提及列表：同一步骤可能重复提到同一地点，不代表重复访问。
- `poi_order=explicit` 表示步骤内部有路线顺序；`unspecified` 表示并列地点内部顺序未知；`single` 表示单个或未识别具体地点。跨步骤按 `step_id` 读顺序。
- `kind` 区分 `poi`、`station`、`boundary`、`unresolved`；`scope=surrounding` 标出神仙池、九寨沟县城、漳扎镇等外围行程，不能因为文档景区为九寨沟就把它们归进九寨沟景区内部。

所有位置以原样 `clean_text` 为基准，Python Unicode 码点索引，从 0 开始，左闭右开。`evidence.text == clean_text[start:end]`。不重新清洗正文，也不使用 UTF-8 字节或 JavaScript UTF-16 偏移。

九寨沟一日游直接使用“上午/中午/下午”标题。游客样本有明确时刻时，使用可复现的分桶规则：11:30 前为上午，11:30–13:30 前为中午，13:30–18:00 前为下午，之后为晚上；这些边界是本实验的归一化约定，不证明作者在该时段用餐。

`null` 表示原文未注明日期或时段。故宫、西湖原文主要给出访问顺序，部分只给总时长，因此保留未知时段；“3小时”不转换成“上午”。二日/三日游有日期但没有时段，则使用“第 N 天→未注明时段”。

`clock_range_minutes` 只把原文时刻转成当日分钟；多站共享一个区间时不拆分。`visit_duration_text` 与 `travel_duration_text` 分开，均有原文锚点。“参观”作为默认活动时 `activity_inferred=true`，表示解析补充的概括，而不是原文事实。

## 名称、噪声与重复

官方路线的显式节点直接从结构中提取，能保留 V2 漏识别的节点。游客片段使用该位置的 V2 POI 加本景区官方路线名称词表，重叠候选优先保留长名称；全文背景实体不直接进入路线。

仅在九寨沟配置两个映射：`天鹅湖→天鹅海`、`诺日朗中心→诺日朗中心站`。前者依据同一官方指南中的景点概述与相邻路线节点推断，后者依据游记的换乘语境；属于显式规则假设，原词和位置始终保留。单写“诺日朗”仍保留为 `unresolved`，不参与景点指标。其他简称或同义关系不自动推断。

“雷峰夕照/雷峰塔”“南屏晚钟/净慈寺”、父区域/子景点保持不同名称。括号中的别称、遗址、附属地点不直接合并。无序并列节点保留在同一步中，不建立它们之间的先后关系。

不同备选路线、不同日期可以包含相同景点，不能全局去重。计算路线序列时仅折叠相邻同名提及，保留非相邻的返回访问。覆盖度用集合计算。对内部顺序未知的多地点步骤，顺序比较函数拒绝强行展平；当前选定三组对比路线均具有可读顺序。

## 对比口径

每个景区选定一条主题接近的官方方案：故宫路线一、西湖十景文化之旅、九寨沟一日精华游。对应游客样本与选择理由写在 `samples.json`。故宫、西湖属于游客发布的推荐攻略，仅九寨沟样本明确自述实走；结果不能统称为三景区实测轨迹比较。

在参与对比的景区内部具名景点序列上，排除交通站、泛称出入口、未消歧节点和外围节点。设官方序列为 A、游客序列为 B，集合分别为 U、V：

- 官方景点覆盖率：`|U∩V| / |U|`。
- 景点集合 Jaccard：`|U∩V| / |U∪V|`。
- 顺序相似度：`2 × LCS(A,B) / (len(A)+len(B))`。LCS 为最长公共子序列；只交换访问顺序也会降低此指标。

`strict` 使用原名字面，`normalized` 使用上述限定映射。当前三组对比的景点指标相同：涉及归一化的换乘站被排除，天鹅湖写法仅出现在多日官方方案中。

时间部分列出原文总时长、首末时刻差及显式游览时长条数。九寨沟官方片段为 07:00–17:35，游客为 10:00–17:45，首末差分别为 635 和 465 分钟；不将差值解释为交通/停留时长或效率提升。官方末段时间重叠也会限制此比较。游客没有逐站停留时间，不能由相邻到站时刻反推。

## 验证与已知边界

20 项相关测试覆盖三景区格式、时间层级、并列与括号、共享时段、重叠时刻、外围节点、限定别名、游客截取、Unicode 索引及指标计算。每次运行另检查全部输出的切片、层级与步骤引用。测试使用固定真实语料与少量边界样例，没有进行网络调用或整仓测试。

`results/QUALITY.md` 是可再生成的程序检查及代码辅助复核记录。它不代表学生已经人工签字，也不提供整体 Precision/Recall/F1；提交前应结合原文人工确认。原文可能过时的票务、开放时间不作为本实验的实时旅游建议。

下游读取路线文件时，以 `doc_id` 回查正文，以 `route_id` 区分备选方案；保留 `evidence` 和 `issues`。共享时间段、未展开的 `components`、并列地点和未知时段都需要保留原有语义。
