# 实验项目2 游览步骤的实体识别

## 2.1 数据范围与实体定义规范

沿用项目 1 的 `task1/data/final/documents.jsonl`，取全部 18 篇的 `clean_text`，包含正文、保留的标题与路线列表，不重清洗。输入 SHA-256：`a00d04703a53c515a39a39a74582f1e6d00f7098474460eec7ecb93a722c3a65`。字符数包括空白和标点。输入统计如下。

| 景区 | 官方路线篇数 / 字符数 | 游客游记篇数 / 字符数 / 单篇范围 |
|---|---:|---:|
| 北京故宫 | 1 / 4,249 | 5 / 3,902 / 454–994 |
| 杭州西湖 | 1 / 2,616 | 5 / 3,297 / 395–957 |
| 九寨沟 | 1 / 2,404 | 5 / 4,461 / 808–996 |
| 合计 | 3 / 9,269 | 15 / 11,660 / 395–996 |

| 实体 | 定义与边界 | 正例 | 不标注的情况 |
|---|---|---|---|
| POI | 取可定位的访问点、景点或交通节点的连续名称 | 午门、断桥残雪、黄龙九寨站 | 普通地点“景区门口”，路线分组“右线”，背景中出现的城市名 |
| TRANSPORT | 明确的出行方式或线路 | 步行、地铁 1 号线、观光车 | 泛动作“走”、票务商品“游船联票” |
| TIME | 与游览、开放、预约、交通相关的日期、时刻、时段或时长；保留范围和约数 | 10.17、中午12点前、约10分钟 | 历史背景“南宋”，时长的字段前缀“游览时间”和后缀“车程” |

父景区、子景点和独立提到的历史别名按各自位置标注，完整名称内的简称不另计。具名交通站点可以作 POI，城市背景和路线分组排除。具名景观集合按能否指向整体访问点判断。工具名和表达明确方式的动作短语均可作 TRANSPORT，泛指的“坐车”暂按“乘车”排除。TIME 依据所限定的行为判断，预约复合约束可整体保留，独立的推荐时段分别标注。原规范及收尾时补充的判定口径分别保存在 [ENTITY_SPEC.md](ENTITY_SPEC.md)。

## 2.2 识别方法设计与实现

用 DeepSeek 处理自然语言、景区专名和列表内多样的时段表达。仅用 Python 标准库调用 API，模型 `deepseek-flash`，关闭思考，temperature=0，max_tokens=2400，启用 JSON Object 模式。V1 要求只复制原文，输出 `entities` 数组，每项含 `text`、`type`，允许同形歧义时加 `occurrence`。V2 只改变 Prompt，追加针对已观察到的历史时间、路线分组、票务、时长边界及重复输出的复查清单。完整提示和配置见 `prompts/` 与 `config.json`。

文本长于 2400 字符时，优先在 1600–2400 字符区间内的最后一个句尾或换行处分块；21 块无重叠，保留原文偏移。调用保存原始响应、用量与日志，暂时性错误或无效 JSON 最多尝试三次，相同请求使用本地缓存。两轮均成功完成 21 块。API 记录输入 52,920 tokens（其中缓存命中 10,240），输出 20,820 tokens；按本次查阅的 [DeepSeek Flash 峰时单价](https://api-docs.deepseek.com/quick_start/pricing) 估算约 0.038 美元，实际账单以平台为准。依次运行 `python task2/run.py v1`、`python task2/run.py v2`、`python task2/analyze.py` 可重建成果，已有缓存时不需要联网。

## 2.3 实体输出与位置记录

两轮各输出 `entities.json`、`issues.json`、`run.json`。实体保留原文 `text`、`type`、`doc_id`、景区、来源类型、文档类型、来源名、URL、分块与全文位置。Python 在分块内逐字寻找原文，默认保留所有匹配，模型可以用从 1 开始的出现序号限制匹配；加上分块起点后得到全文 Unicode 字符位置。使用 0-based 左闭右开区间 `[start,end)`，无法定位时只记异常。长跨度优先解决重叠，完全相同跨度的跨标签冲突不自动猜测类型。

例如 V2 的 `jiuzhaigou_official_88ef5cc31789dc71` [411,415) 切片为“20分钟”，类型 TIME。两轮分别有 1,503、1,415 条通过切片校验，错位均为 0。相同文字在不同位置各有记录。

## 2.4 人工抽查与质量分析

按三景区 × 两类来源抽取六组片段。每组取固定输入顺序的首篇，截取前 220 字，最多向后延伸 50 字到下一换行。原文、两版完整落入窗口的预测、全文字符偏移和裁决均保存在 [六组样本核验记录](results/analysis/human_review.md)。学生已在 AI 辅助初审基础上完成六组样本确认。

两轮在这些片段中分别记录 20/17 条 FP、2/7 条 FN、1/1 条边界偏差和 0/0 条有效实体的跨标签错误。西湖官方“题名景观形成于南宋”中的“南宋”[147,149) 两轮均误报为 TIME。“五一假期前”与“五一假期”均修饰资料整理，两版各计一条 FP。九寨沟官方“上下季节海”[189,194) 两轮均只命中其中的“下季节海”[190,194)，学生确认应保留完整合称，计一条边界偏差。故宫游记“提前7天的20:00”[171,181) 整体作为预约约束保留。学生确认泛称“坐车”排除，三处“西湖十景”各计一次 POI 误报，图件索引中的“紫禁城”[105,108) 在两版中各计一次 POI 漏报。

这六组是固定窗口中的定向复核，未建立完整人工 gold，所列数量不用于计算 Precision、Recall 或 F1。原始响应、位置检查及其他定向案例见 [QUALITY.md](QUALITY.md)。

## 2.5 三类实体词频可视化与迭代

每个独立出现位置计一次；按原文字面与类型聚合，不合并别名或不同词形，不额外事后过滤停用词。两轮使用同一输入、模型、分块、对齐代码和统计口径。

| 指标 | V1 | V2 |
|---|---:|---:|
| POI | 1,190 | 1,112 |
| TRANSPORT | 124 | 121 |
| TIME | 189 | 182 |
| 总计 | 1,503 | 1,415 |
| 无法定位候选 | 5 | 0 |
| 重复位置事件 | 49 | 24 |
| 重叠剔除事件 | 101 | 103 |

同文档、同位置、同类型保留 1,346 条；V1 独有 157 条，V2 独有 69 条。V2 北京故宫为 372/19/41，杭州西湖为 363/52/37，九寨沟为 377/50/104（POI/TRANSPORT/TIME）。九寨沟 TIME 最多，与该数据中常见的分段行程和到站时刻有关；这些是本样本计数，未控制文本长度、行程格式或文本来源。

追加排除和逐字复核提示后，全量“景区门口”由 2 到 0，“右线”由 14 到 9，五处“游览时间20分钟”全部改为“20分钟”。六组样本中 V2 去掉故宫官方的“北京”和九寨沟游记的两处“景区”，但漏掉九寨沟游记的“树正沟”和“步行”、故宫官方的“紫禁城”、西湖游记的“清晨”和“傍晚”。这五条是本次在六组内查实的退化案例，原始 V2 响应均未给出相应候选。

“南宋”仍有 8 次，重叠剔除由 101 增至 103。字面扩展会误命中同形子串，最长跨度优先也可能丢失具有独立语义的重叠提及。两轮使用相同口径，无法定位与重复事件下降说明相关对齐异常减少，但样本同时显示误报改善与漏报增加。实体总数、重复或定位变化不足以证明整体语义精度提高。
